# Data Model: Document Upload and Management

**Feature**: [spec.md](spec.md)

## Document

Represents an uploaded work-related file and its searchable metadata.

| Field | Type / rule | Notes |
|---|---|---|
| `DocumentId` | Integer, required, unique | Preserves the existing key convention. |
| `Title` | Text, required | User-facing title; duplicate titles are allowed. |
| `Description` | Text, optional | Searchable description. |
| `Category` | Text, required | One of Project Documents, Team Resources, Personal Files, Reports, Presentations, or Other. |
| `Tags` | Text, optional | User-provided searchable tags. |
| `ProjectId` | Integer, optional | References a project when the document is project-related. |
| `TaskId` | Integer, optional | References a task when attached in task context. |
| `UploaderUserId` | Integer, required | References the user who uploaded the document. |
| `OriginalFileName` | Text, required | Display/download metadata only; never used as a trusted storage path. |
| `StoredFilePath` | Text, required, unique | Relative generated path outside `wwwroot`; must not be empty. |
| `FileSize` | Integer/long, required | Bytes; maximum 25 MB per file. |
| `FileType` | Text, required, max 255 characters | MIME type captured at upload. |
| `UploadedDate` | UTC datetime, required | Creation timestamp. |
| `UpdatedDate` | UTC datetime, required | Last metadata or file replacement timestamp. |
| `SecurityStatus` | Text, required | Pending, Scanning, Available, Rejected, or ScanFailed. Only Available is user-accessible. |
| `ScanVersion` | Text, required | Version/correlation token that makes repeated queue deliveries and late scan results safe. |
| `ScanAttemptCount` | Integer, required | Number of dispatched or processed scan attempts. |
| `ScanUpdatedDate` | UTC datetime, optional | Last scan state transition. |
| `ScanFailureReason` | Text, optional | Non-sensitive operator-facing failure classification; do not store scanner secrets or raw payloads. |

### Validation rules

- Required title and category must be present before persistence.
- Category must match the predefined text values.
- File extension and content type must match the supported allowlist: PDF, Word, Excel, PowerPoint, plain text, JPEG, and PNG.
- File size must be at most 25 MB.
- Malware validation must succeed before `SecurityStatus` becomes Available; unavailable scanning must not expose the file.
- A scan result applies only when its document identifier and `ScanVersion` still match the current document version.
- `StoredFilePath` must be generated by the application and remain relative to the configured storage root.
- A failed file write must not create an accessible metadata record; a failed metadata write must trigger cleanup of the saved file.

## DocumentShare

Represents an explicit permission granted by a document owner to a user or team.

| Field | Type / rule | Notes |
|---|---|---|
| `DocumentShareId` | Integer, required, unique | Share identity. |
| `DocumentId` | Integer, required | References `Document`. |
| `SharedByUserId` | Integer, required | Must be the owner or an administrator acting with authority. |
| `RecipientUserId` | Integer, optional | Set for an individual recipient. |
| `RecipientTeamKey` | Text, optional | Set for a team recipient using the existing team/department identity. |
| `SharedDate` | UTC datetime, required | Creation timestamp. |
| `RevokedDate` | UTC datetime, optional | Set when the owner or administrator revokes the share. |

### Integrity rules

- Exactly one recipient target must be set for each share.
- Duplicate active shares for the same document and recipient are not allowed.
- A revoked share grants no access and remains available for audit history.
- Project membership access is evaluated separately from explicit shares and is not represented as a duplicate share row.

## DocumentAuditEvent

Records security-relevant document operations for authorized administrators.

| Field | Type / rule | Notes |
|---|---|---|
| `DocumentAuditEventId` | Integer, required, unique | Audit identity. |
| `DocumentId` | Integer, required when target exists | Target document; retain a safe reference for failed or denied requests where possible. |
| `ActorUserId` | Integer, required | User who attempted or completed the operation. |
| `Action` | Text, required | Upload, Download, Preview, MetadataUpdate, Replace, Delete, Share, RevokeShare, or AccessDenied. |
| `Outcome` | Text, required | Success, Rejected, Failed, or Denied. |
| `CreatedDate` | UTC datetime, required | Event time. |
| `Context` | Text, optional | Non-sensitive reason or request context; never store file contents, secrets, or raw paths. |

## Notification integration

Existing `Notification` rows are created for successful document shares and new project documents. Document notifications must identify the event and target document without revealing content to users who are not authorized to access it. The existing user-specific read/unread behavior remains unchanged.

## Relationships

```text
User 1 --- * Document (uploader)
User 1 --- * DocumentShare (recipient or sharer)
Team/Department 1 --- * DocumentShare (team recipient)
Project 1 --- * Document
Task 0..1 --- * Document
Document 1 --- * DocumentShare
Document 1 --- * DocumentAuditEvent
User 1 --- * DocumentAuditEvent (actor)
User 1 --- * Notification
```

## Access evaluation

A request is authorized when at least one applicable rule is true:

1. The requester is the document owner.
2. The requester is an administrator.
3. The document has a project and the requester is the project manager or an active project member.
4. The requester has an active explicit share as an individual or team recipient.

Mutation rules are stricter: metadata update, replacement, deletion, sharing, and share revocation require document ownership, project-manager authority where specified, or administrator authority. Every operation re-evaluates current relationships before reading or changing file content.

## State transitions

```text
New metadata -> Pending -> Scanning -> Available
                                  \-> Rejected
                                  \-> ScanFailed
Pending/Scanning -> retry -> Scanning
Available -> Replaced -> Pending
Available -> Deleted (terminal; file and metadata removed)
Active share -> Revoked (terminal for that share)
```

Only `Available` documents participate in browse, search, preview, download, project, task, dashboard, and share results. `ScanFailed` is terminal until an authorized retry creates a new scan version.

## Query/index expectations

Indexes should support:

- `UploaderUserId` plus `UploadedDate` for My Documents and Recent Documents.
- `ProjectId` plus `SecurityStatus` for project document lists.
- `Category`, `UploadedDate`, and `FileSize` for filters and sorting.
- Active share lookups by `DocumentId`, `RecipientUserId`, and `RecipientTeamKey`.
- Audit queries by `DocumentId`, `ActorUserId`, `Action`, and `CreatedDate`.

Search queries must apply authorization and `SecurityStatus == Available` before returning results.
